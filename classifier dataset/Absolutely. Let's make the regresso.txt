# BLOCK 2 — Calculate all regression metrics

```python
from sklearn.metrics import (
    mean_absolute_error,
    mean_squared_error,
    r2_score
)

mae = mean_absolute_error(
    y_test,
    y_pred
)

mse = mean_squared_error(
    y_test,
    y_pred
)

rmse = np.sqrt(mse)

r2 = r2_score(
    y_test,
    y_pred
)

print("=" * 55)
```

```python
print("""
METRIC INTERPRETATION
---------------------

MAE:
Average absolute difference between actual and predicted discount.

MSE:
Average squared prediction error.
Larger errors are penalized more heavily.

RMSE:
Square root of MSE.
It represents prediction error in the same unit as discount percentage.

R²:
Shows how much variation in recommended discount is explained by the model.
Higher values generally indicate better fit.
""")
```

## ⭐ One more thing I recommend adding

For your **DealFlow360 demo**, don't stop at:

> "Our model predicts 12.7%."

Make the ML output useful to the **rule engine**:

```text
Customer
   ↓
Product
   ↓
Historical Transactions
   ↓
XGBoost Regressor
   ↓
Recommended Discount = 12.7%
   ↓
────────────────────────────
      RULE ENGINE
────────────────────────────
Customer Tier Limit = 15%
Product Limit        = 14%
Minimum Margin       = 18%
────────────────────────────
          ↓
     12.7% allowed
          ↓
      Continue
```

And if the model says:

```text
Recommended Discount = 18%
```

but:

```text
Customer Limit = 15%
```

then:

```text
XGBoost
   ↓
18% recommendation
   ↓
Rule Engine
   ↓
❌ Exceeds customer limit
   ↓
Discount Risk Classifier
   ↓
HIGH RISK — 87%
   ↓
Approval Engine
   ↓
Manager Approval
```

That gives you a **much stronger architecture** than simply putting an ML model into the project:

> **Regressor recommends → Rule Engine validates → Classifier assesses risk → Approval Engine decides → Deal is committed.**

And importantly, the ML model **never gets authority to approve a discount**. The rules remain deterministic and auditable.
